# 🐸 David Finance AI

### Учёт финансов с характером

Следите за расходами, планируйте бюджет и обсуждайте свои финансовые решения с Давидом Жабовым — ИИ-помощником, который умеет не только анализировать траты, но и с юмором комментировать покупки.

**David Finance AI** — Android-приложение с локальной историей операций, целями, долгами, аналитикой и тёмным интерфейсом **Obsidian Neo-Bank**. Базовый учёт работает без Gemini; для ИИ-функций нужны сеть, API-ключ и доступная модель.

> **Статус: активная разработка.** Это приложение для личного учёта, а не банковский сервис или профессиональная финансовая консультация. Отдельные функции и сценарии ещё проходят тестирование.

## Как выглядит приложение

Скриншоты главного экрана, диалога с Давидом, голосового ввода и аналитики будут добавлены после подготовки изображений без личных финансовых данных.

## Возможности

- **Бюджет и операции:** учёт доходов и расходов, категории, лимиты, история и поиск операций, сводка за период.
- **Safe-to-Spend:** расчёт ориентировочной доступной суммы для ежедневных расходов на основе данных бюджета. Это информационная оценка, а не гарантия отсутствия кассового разрыва.
- **Аналитика:** структура расходов, динамика по периодам, годовая сводка и сравнение показателей.
- **Ввод операций:** ручное добавление, голосовое распознавание при наличии соответствующих разрешений и сервисов устройства, локальный разбор текста и интеграция с Gemini для ИИ-обработки.
- **Давид Жабов 🐸:** чат о личном бюджете, анализ трат, юмористический режим «прожарки», предложения операций с подтверждением пользователя.
- **Геймификация:** достижения, опыт и ранги.
- **Цели и накопления:** отслеживание прогресса и пополнение копилок.
- **Долги и займы:** учёт сумм «я должен» / «мне должны» и погашений.
- **Данные:** локальное хранение в Room, импорт и экспорт JSON, демонстрационные данные.

Функции, использующие Gemini, требуют действующего API-ключа, подключения к сети и доступности выбранной модели. Базовый локальный учёт не требует Gemini. Голосовое распознавание не следует считать полностью офлайн-функцией: это зависит от устройства и используемого сервиса распознавания.

## Новые возможности текущей ветки main

### David Live — голосовой диалог с Давидом

- Двусторонний голосовой разговор через Gemini Live API: потоковая передача аудио, голосовые ответы и субтитры в реальном времени.
- Возможность перебить ответ Давида (barge-in), свернуть и развернуть голосовую панель; отдельный режим не запускается одновременно с обычным голосовым вводом операций.
- Круговой спектральный визуализатор реагирует на аудиосигнал.
- Для ответов о реальных финансах Live использует **инструменты только для чтения**: финансовая сводка, траты по категориям, цели и долги, сравнение периодов, последние транзакции. Он не должен выдавать неподтверждённые цифры за факты или самостоятельно изменять записи.
- После содержательного разговора формируется карточка итогов на основе диалога и проверенных финансовых фактов; предусмотрена обработка ошибок и повторная попытка.
- Для Live требуется вручную указанный пользователем Gemini API-ключ, доступ к сети и микрофону. Доступность голосовых моделей зависит от Gemini API.

### Голосовой ввод и визуальные эффекты

- Отдельный сценарий голосового ввода финансовых операций, включая обработку распознанного текста.
- Спектральный 32-полосный визуализатор, анализатор PCM/FFT и неоновое оформление голосовой панели; это **не тот же самый** круговой визуализатор David Live.
- Фирменные анимации и тёмная тема Obsidian Neo-Bank.

### Настройки, аналитика и персонализация

- Настраиваемая строгость финансового аудитора и триггеры для крупных, импульсивных и ночных расходов; порог «кваканья».
- Напоминания и настраиваемые сценарии уведомлений, включая умный вечерний чек-ин (при наличии разрешений).
- Расширенные экраны истории операций: поиск, фильтры, сортировка, сравнение, диаграммы и детализация.
- Разделение расходов, годовые отчёты, лимиты бюджета, цели, долги и достижения.
- Настройки голоса и ИИ, резервное копирование/восстановление, параметры безопасности и приватности.

**Примечание:** наличие функции в исходном коде не гарантирует её работоспособность на каждом устройстве или с любым Gemini API-ключом. Проект активно развивается; перед выпуском проверяйте CI и работу на реальном устройстве.

## Начало работы

### Требования

- Android Studio с поддержкой используемых версий Android Gradle Plugin и Kotlin;
- Android SDK, необходимый для `compileSdk` (см. `app/build.gradle.kts`);
- JDK, совместимый с Gradle Wrapper и Android Gradle Plugin проекта;
- устройство или эмулятор Android 7.0 (API 24) и выше.

### Сборка

1. Склонируйте **свой** репозиторий или распакуйте архив проекта.
2. Откройте корневую папку в Android Studio и дождитесь Gradle Sync.
3. Для функций Gemini создайте ключ в Google AI Studio. Скопируйте `.env.example` в `.env` и замените значение `GEMINI_API_KEY` либо используйте предусмотренный приложением ввод ключа.
4. Не коммитьте `.env`, реальные ключи, пароли подписи и keystore в публичный репозиторий.
5. Соберите debug APK:

```bash
./gradlew :app:assembleDebug
```

На Windows:

```powershell
.\gradlew.bat :app:assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`.

Для запуска тестов (если среда настроена):

```bash
./gradlew :app:testDebugUnitTest
```

Инструментальные тесты требуют подключённого устройства или эмулятора:

```bash
./gradlew :app:connectedDebugAndroidTest
```

**Важно:** конфигурация релизной подписи в `app/build.gradle.kts` использует переменные окружения `STORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS` и файл `my-upload-key.jks`; при его отсутствии предусмотрен fallback на debug keystore. APK, подписанный debug-ключом, не следует публиковать как production-релиз. Перед выпуском настройте собственную безопасную релизную подпись и проверьте CI.

## Приватность и ограничения безопасности

- Финансовые записи хранятся локально в базе Room (обычный SQLite). **Шифрование файла базы данных на уровне SQLCipher или эквивалентного решения не заявляется.**
- Для части настроек используется `EncryptedSharedPreferences`, но текущая реализация `SecurityManager` допускает fallback на обычный `SharedPreferences`, если инициализация защищённого хранилища завершилась ошибкой. Это требует исправления и отдельной проверки перед публичным релизом.
- PIN и биометрия ограничивают доступ через интерфейс приложения, но сами по себе не означают шифрование всех данных на устройстве.
- При обращении к Gemini соответствующие данные запроса отправляются внешнему API. Не передавайте чувствительные сведения без понимания условий обработки данных и согласия пользователя.
- JSON-экспорт может содержать личную финансовую информацию: храните резервные копии в безопасном месте и не публикуйте их.
- ИИ-ответы и расчёты могут содержать ошибки; приложение не заменяет профессиональную финансовую консультацию.

Подробнее: [PRIVACY_POLICY.md](PRIVACY_POLICY.md). Перед публикацией необходимо сверить этот документ с фактическим поведением приложения.

## Что проверить перед релизом

- Убрать небезопасный fallback для секретов и определить стратегию обработки ошибок шифрования.
- Проверить защиту локальной БД, экспортируемых резервных копий и журналов.
- Добавить тесты финансовых расчётов, импорта/экспорта и миграций Room; рассмотреть `exportSchema = true`.
- Проверить доступность используемых Gemini-моделей и поведение при ошибках API, отсутствии ключа и сети.
- Настроить production-подпись, секреты CI и проверить релизную сборку на реальном устройстве.
