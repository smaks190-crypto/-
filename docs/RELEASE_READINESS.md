# Подготовка David Finance к релизу

Статус: подготовка продолжается. Успешная сборка сама по себе не означает готовность всех экранов и сценариев.

## Согласованные решения

- После системного выбора файла запрашивается PIN; выбранный документ сохраняется до разблокировки и затем импортируется один раз.
- Тёмная тема остаётся основной; единые шрифты, скругления и спокойные поверхности, меньше декоративных эффектов.
- Защитный резерв неприкосновенен, в том числе для базовых расходов.
- В облачке голосового помощника отображается разговор. Настройки и ошибки связи показываются отдельно, один раз.

## Исправления и проверки

- Регистрация выбора документа вынесена выше условного экрана PIN; URI сохраняется через recreation. Сам импорт выполняется в ViewModel и не отменяется при повороте. Чтение файла ограничено 10 МиБ и выполняется вне главного потока.
- Тест на устройстве проверяет получение результата при блокировке, восстановление состояния и однократное продолжение после разблокировки.
- В прогнозе доходы используют исходную сумму, а не верхнюю оценку; перенесённые поступления исключаются из старой даты. Базовые траты ограничены защитным резервом и прогнозом обязательств.
- Дополнены тесты финансовых ограничений и монотонности резерва.
- Подключён desugaring java.time для заявленного Android 7 (API 24).
- Добавлена проверка UI на эмуляторе и сохранение скриншотов голосовой панели.

## Оценка финансового алгоритма

Основа разумная: детерминированная проекция ликвидности по дням, разделение гарантированных и ожидаемых доходов, резервирование обязательств, исключение оплаченных платежей. Это лучше простого деления остатка на число дней.

Риски, которые нужно закрыть до обещания финансовой точности:

1. Деньги пока Double: нужен единый переход БД, JSON и вычислений на целые копейки с миграциями и тестами округления.
2. Достоверность прогноза зависит от полноты внесённых счетов и регулярных обязательств. При недостатке истории интерфейс должен явно показывать низкую уверенность, а не гарантировать безопасность трат.
3. Проверить длительную просрочку: генератор повторений ограничен 400 итерациями и требует отдельного решения для многолетних ежедневных правил.
4. Пройти все входы в операции: ручной ввод, голос, ИИ, импорт; единые ограничения сумм и дат обязательны на уровне доменной логики.
5. Проверить согласованность балансов при переводах, погашении долгов и взносах в цели на наборах реальных обезличенных данных.

## Релизные критерии

- Проходят unit-тесты, сборка release и инструментальные сценарии PIN/импорт/выбор бюджета/голосовая панель.
- Проверены API 24, современный Android, крупный шрифт, маленький экран, поворот, background и потеря процесса.
- Проверены отсутствие сети/ключа/микрофона, восстановление соединения, завершение голосовой сессии, аудиофокус и расход батареи.
- Все экраны сведены к общей системе компонентов и просмотрены на скриншотах; диалоги не обрезаются клавиатурой и системными панелями.
- Пройдены миграции Room, сохранение/восстановление JSON и ручная проверка подписанного APK на телефоне.
- Политика приватности соответствует сетевым запросам, системным backup и экспорту; определена стратегия защиты незашифрованной SQLite/JSON.

Не закрытые критерии остаются блокерами выпуска, а не скрываются под формулировкой «релизный уровень».

## Тестовая сборка

Debug-сборка устанавливается как отдельное приложение «David Finance · Тест» с идентификатором `ru.personalbudget.app.aadece.preview`. Она не заменяет установленную основную версию и использует собственную базу, настройки PIN и API-ключ. Для проверки импорта используйте JSON-копию, экспортированную из основной версии; удалять основную версию не нужно. Эта сборка подписана debug-ключом и предназначена для проверки, а не для публикации в магазине.
